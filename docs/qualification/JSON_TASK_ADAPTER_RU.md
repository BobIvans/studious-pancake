# Запуск аудита квалификации через JSON

Этот адаптер даёт OCC, локальному маршрутизатору Laya и API-клиенту один проверяемый вход в существующий офлайн-аудит MPR-2611. Он вызывает `run_repeated` из `scripts/run_mpr2611_clean_qualification.py`. Владельцы доказательств и допуска остаются прежними.

## Что выполняется

1. Проверка точного JSON-контракта и полного SHA текущего чистого checkout.
2. Два или больше пересчёта имеющихся доказательств квалификации.
3. Сохранение блокеров и квитанции с SHA256 вне checkout.
4. Повторный запрос с тем же task_id возвращает исходную квитанцию без нового исполнения.

Это аудит сохранённых доказательств, а не запуск кампании на новых RPC-наблюдениях. `campaign_executed=false`. `CHECKED_BLOCKED` означает, что аудит состоялся, но квалификация заблокирована. Даже `CHECKED_REVIEW_ELIGIBLE` не разрешает live или выпуск.

## Запрос и команда

В активном Python 3.13 окружении создайте JSON вне checkout. Значение source_commit должно совпадать с `git rev-parse HEAD` именно той ветки, где установлен адаптер.

```json
{
  "schema_version": "qualification-task.v1",
  "task_id": "qualification-audit-001",
  "action": "qualification.audit",
  "source_commit": "REPLACE_WITH_CURRENT_40_CHARACTER_COMMIT_SHA",
  "release_id": "local-audit-001",
  "repeat": 2
}
```

```bash
python scripts/run_qualification_task.py --request ../request.json --output-root ../qualification-receipts
```

Коды выхода: 0 — аудит допускает рассмотрение release; 3 — аудит завершён, квалификация BLOCKED; 2 — ошибка запроса, идентичности, стабильности или квитанции. Диспетчер должен отдельно обработать код 3, не запускать бесконечные retries и показать blockers.

## Подключение модели

Модель предлагает только поля запроса. Исполнитель сам задаёт доверенный checkout и output-root. Произвольные shell-команды, пути, действия и дополнительные поля отвергаются. Установка Laya и вызов OpenAI API не требуются для запуска аудита.

Новый набор доказательств проверяйте с новым task_id. Replay возвращает исторический результат первого запуска и не подтверждает свежесть текущих файлов доказательств. Квитанция хранится локально; SHA256 обнаруживает повреждение, но не является подписью от независимого доверенного производителя.

После прерванного запуска каталог без receipt.json сохраняется. Повтор получает TASK_INCOMPLETE_OR_CONCURRENT. Осмотрите каталог и используйте новый task_id для нового явного запуска. Автоматическая обработка зависших claims и фоновое расписание в этот PR не входят.

## Следующее изменение

Подключить получение реальных sender-free наблюдений через существующий поддерживаемый runtime после закрытия provider/protocol blockers. Аудит не меняет MarginFi PAUSED, обязательность проверки Slumlord и действующий запрет live.
