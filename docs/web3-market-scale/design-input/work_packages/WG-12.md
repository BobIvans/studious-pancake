## Шаги будущей реализации

1. Расширить/адаптировать SharedExecutionState в его owner: reserves, ticks/bins, book consumption нужны сверх capacity counters.
2. Переиспользовать solve_joint_split_flow для allocation/order enumeration; native-currency sizing остаётся PR118.
3. Сравнивать same-budget single и split baseline; фиксированные/общие costs применять один раз на правильном уровне.
4. Доказать отсутствие двойного расходования shared pools, collateral и funding capacity.

## Приёмка

- Порядок ветвей влияет на state и проверяется; initial state immutable.
- Split promotion только complete bounded search и strict net improvement; все residual debts закрыты в модели.

Сценарии: T41, T42, T43, T44; определения в `../06_ACCEPTANCE_RU.md`.

## Ограничения

Первая integration: 2 paths, finite allocation grid и max evaluations; существующий max_paths5 не означает бесконечный solver.

## Когда остановить admission

State aliasing, missing common-cost model или shared resource неизвестен → split disabled.

Не создаёт live authorization. Размер diff и оценку труда определить после обновления baseline; новые owner дубликаты не вводить.
