# Solana flash-capital — pinned offline technical dossiers
Audited: 2026-10-08. Sources recorded in SOURCE_LEDGER.json. These notes are factual summaries and review/implementation rules, not instructions to execute.

## Jupiter Lend — preferred no-margin-position candidate (JUPITER_LEND)
**Official**: developers.jup.ag/docs/lend/flashloan and /execute; source docs repo jup-ag/docs@1de8fd08f9ae17b38b9c4f07eb29637d6e2182a7, path lend/flashloan/{index,execute}.mdx. Official Jupiter agent skill jup-ag/agent-skills@a2211e3f6a7caa03310c7a9a8d816e723b0bdc5f.
- Module: `@jup-ag/lend/flashloan`; `getFlashloanIx({connection: Connection, signer: PublicKey, asset: PublicKey, amount: BN}) -> {borrowIx,paybackIx}`; `getFlashBorrowIx` and `getFlashPaybackIx` are separately exposed. Borrow, arbitrary custom instructions, payback in the *same* transaction. Borrow and payback are expected to bracket operations; compute budget instruction can precede them.
- Docs declare **zero flashloan fee/no collateral**. This is protocol-fee marketing, not proof of a free transaction: network fees charged even on a reverted attempt; ATA setup/rent and a valid SPL Token account may be needed. No separate marginfi account-creation step appears in the official flashloan example; mark `position_init=NOT_IN_PUBLISHED_FLOW`, not irrevocable `NONE`.
- Code owners already present: `src/lending/jupiter_lend.py` (pinned program ID/PDA, FlashloanAdmin 93-byte layout, Borsh decoder) and `src/lending/agg03_financing_ports.py` (JupiterLendFinancingSnapshot/port). Snapshot currently requires admin status true, no active loan, zero admin fee, matching liquidity program, positive live capacity; no fake blanket zero.
- Required R02 read: validate program owner/genesis + admin PDA+decoded status/fee/active amount; reserve liquidity ownership/mint and token-program/decimals; token reserve borrow conditions, immutable source/account binding, slot/quorum and account/gen evidence. If only vault balance is known, cap not independently known => NEGATIVE. Build and execute are R03/R05, not R02.
- Gap: `src/economics/flash_capital_graph/graph.py` whitelist does not yet accept `jupiter_lend`; add minimal allowlist/chain and a single adapter with tests. Do not weaken other providers to fit.

## Kamino Lend / KLend — verified separate flash instructions, no obligation account
**Pinned authoritative source**: Kamino-Finance/klend@a08760976f51a3a58c4a0c6ea27b4a0e565bca79 (release 1.25.0, 2026-08-18). Official SDK Kamino-Finance/klend-sdk@3c3a38d4ff9d7cf7b0380a383b81c9cd4f0f58b8; package.json at pin says `@kamino-finance/klend-sdk@13.0.2`.
- Official klend path `libs/klend-interface/src/instructions/flash.rs` declares `flash_borrow_reserve_liquidity` and `flash_repay_reserve_liquidity`, with repayment `borrow_instruction_index:u8`. Helper `libs/klend-interface/src/helpers/flash.rs` returns `(borrow_ix,repay_ix)`.
- The program account structs in `programs/klend/src/handlers/handler_flash_borrow_reserve_liquidity.rs` and `handler_flash_repay_reserve_liquidity.rs` include `user_transfer_authority: Signer`, reserve, lending market, mint, source/destination token accounts, token programs, fee receiver, sysvar instructions. **No obligation account is listed in these two flash instruction account structs.** This is stronger evidence for no *new lending-position account* than a marketing claim, but wallet ATA can still be required.
- The repay handler calls fee-bearing accounting (`flash_repay_reserve_liquidity`), and can transfer a `reserve_origination_fee`. **DO NOT set protocol fee to zero** merely because P0 or Jupiter is zero. Read fee configuration and effective required repayment per reserve + referral/market rules. Borrow-instruction index must be correct relative to full message instructions.
- Mainnet KLend program as listed by official repo: `KLend2g3cP87fffoy8q1mQqGKjrxjC8boSyAYavgmjD`. Still confirm deployed bytecode/program owner/upgrade authority and market-specific reserve/account layout before R02 positive live state.
- Reuse `src/lending/kamino.py`, `src/lending/kamino_real_conformance.py` and `src/economics/flash_capital_graph/graph.py`; no new Kamino risk/obligation registry. R02 snapshot must come from official reserve decoder pinned to live state, not a fabricated fixture layout. Missing fee/capacity evidence => typed NEGATIVE.

## Project 0 / marginfi — protocol flash fee zero, marginfi account setup still a cost
**Official**: docs.marginfi.com/guides/flashloans, /typescript-sdk/flash-loans, /typescript-sdk/accounts, /protocol-overview/fees, /typescript-sdk/overview, /typescript-sdk/integrations.
- Official SDK now `@0dotxyz/p0-ts-sdk` (>=2.8.0 needed for new oracle setups, according to documentation). Old `@mrgnlabs/marginfi-client-v2` deprecated since March 2026.
- `Project0Client.createMarginfiAccountTx(authority, accountIndex=0,...)` initializes an account PDA; do not call unless later separately authorized. Existing marginfi account can be read only. If missing, provider may remain on research universe but cannot join `NO_NEW_LENDER_ACCOUNT` shortlist.
- Primitive ordering: `lending_account_start_flashloan` first after optional compute budget; `lending_account_end_flashloan` LAST; exactly one flashloan per transaction; **direct instruction only, no CPI for the P0 flash wrapper**. Middle operations can invoke other programs.
- Docs state no protocol flash fee, but rent/ATA/SOL fees remain. Tags for integrated Kamino/Drift/Jupiter banks need scrutiny; do not treat deposit-only integration banks as normal flash borrowing sources.
- Real evidence: dynamic banks filtered per mint, tag, state, max borrow, usable liquidity, oracle, account state and slot. Reuse existing src/providers/marginfi/ shadow builder and capital graph; no second provider engine.

## Save / Solend — DISCOVERY / BLOCKED, not live-ready
Official docs `docs.save.finance/developers/flash-loans` say prior implementation was limited by Solana reentrancy constraints and a future working implementation would be documented. On 2026-10-08 this is **not sufficient proof** of a currently supported general-purpose atomic flashloan on a qualified deployment. A `FlashBorrowReserveLiquidity` symbol in old token-lending instruction code is not a green light. Require pinned deployed implementation, security review, current live instructions, reserve fee/cap and exact end-to-end simulation before enabling. No blind import from legacy solend-sdk.

## No extra Solana providers by assertion
Raydium/Orca/Meteora AMM reserves are tradable DEX liquidity, NOT an automatically borrowable flash-capital pool. A quote-to-trade build race may use them as execution venues, but R02 cannot fabricate lender edges from these pools without explicit atomic flash-borrow ABI proof.
